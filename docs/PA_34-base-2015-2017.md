Research and decision support only, not investment advice.

## 1. Problem

The user chose Option A as the stored base: every F&O underlying, option chain at ±25% moneyness and ≤70 days to
expiry, nothing narrower stored; modelling universes come later as views. Batch a: build 2015–2017 from the raw files
already on disk, with the quality checks of the data-foundation standards, and flag every lot size before 2018 as
UNVERIFIED so nothing can use it for sizing or costs.

## 2. Decisions

| Question | Choice |
|---|---|
| Stored filter | ±25% moneyness, ≤70 days, every underlying (user) |
| Where it lives | New datasets `base_fo_summary` and `base_option_chain`, one file per year. The live `fo_summary` / `option_chain` (31 symbols from 2018), the nightly job and the web app are unchanged |
| Pre-2018 lot sizes | `lot_status = UNVERIFIED` on every row (user). The research loader returns them in `lot_size_unverified` and leaves `lot_size` empty, unless a caller passes `allow_unverified_lots=True` |
| Quality problems in the chain | Flagged in columns, never dropped: `flag_parity`, `flag_below_intrinsic`, with `parity_tested` / `intrinsic_tested` |
| Parity / intrinsic thresholds | Parity off by more than 1% of the same-expiry future; a traded close below discounted intrinsic by more than max(₹0.05, 0.25% of the future). Chosen before the run, not tuned |
| Overwrites | A file about to be replaced is copied to `<store>/_snapshots/` first (none existed for this batch) |

## 3. What was built

| Piece | What it does |
|---|---|
| `base_store.build_day` | One raw file → summary and chain for every symbol in it, with the store's own parser, filter and lot method |
| `base_store.build_years` | A batch of years in parallel; lots despiked per symbol across the batch; `known_from` from the F&O sessions plus the archive holes; writes the year files and `base_manifest.json` |
| `base_manifest.json` | Per dataset and year: rows, date range, SHA-256, bytes, source, download dates, build time |
| `scripts/quant_check_base.py` | The quality checks below; writes the > 5σ moves to `<store>/base_jumps.csv` |
| `loader.BASE` | The research loader serves both datasets, with the point-in-time check and the holdout locks |

## 5. Tests

`tests/test_base_store.py`: every underlying kept with its kind and a derived lot; parity and intrinsic flags set on
the right rows and no row dropped; untraded rows never tested; every pre-2018 lot UNVERIFIED; the loader masks them
unless asked. `tests/test_research_store_pit.py` (opt-in) now covers the base tables: 11 passed on the real store.
Full suite: 1,696 passed, 17 skipped.

## 6. Risks and open items

- **The base has 2015–2017 only.** 2018–2026 for every underlying is not in any batch the user listed (the live store
  has 31 symbols there). Raised with the user.
- The parity flag rate (9.6%) reflects closing prices taken at different moments as much as real violations; the
  flag says "inconsistent at the close", not "wrong".
- The > 5σ list is not matched to corporate actions.
- Lot sizes before 2018 stay unusable for sizing and costs until checked against NSE circulars.
